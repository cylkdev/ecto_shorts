Rule: Rule: Assign Generated AST to Variables Before Unquoting

---

When writing Elixir macros, any Abstract Syntax Tree (AST) that is generated by a function must be computed outside of the quote block. The result should be assigned to a named variable, and this variable should then be unquoted inside the quote do ... end expression. Directly calling a function that returns AST inside the quote block with unquote(...) is discouraged, even if the function is pure.

The primary reason for this rule is to ensure a clear separation between the compile-time generation of AST and the construction of the quoted expression. This practice improves the readability and intent of macros by isolating the side that performs computation (the function call) from the side that emits quoted code (macro output). It also avoids hygiene problems and unquoting edge cases that arise when embedding dynamically generated AST directly within quote blocks. Assigning intermediate AST to variables also makes debugging easier because you can inspect or transform the AST before it is injected.

Valid example

```elixir

ast = generate_ast(:foo)

quote do
    unquote(ast)
end

```

Invalid example

```elixir

quote do
    unquote(generate_ast(:foo))
end

```

---

Auto-correct strategy

Extract the function call from the quote block, assign it to a variable, and unquote the variable.

Before

```elixir

quote do
    unquote(build_expr(:==, bindings, key, nil))
end

```

After

```elixir

expr_ast = build_expr(:==, bindings, key, nil)

quote do
    unquote(expr_ast)
end

```
